Detailed Guide

Using CourseCapture & What-ifs

What each step of capturing a course does and why, and how what-ifs, the course list and the public profile fit around it. For the screen-by-screen steps, use the how-to.

Audience faculty capturing their own courses Time per course 20–45 minutes for a first capture Updated 2026-11-14
01

Overview

CourseCapture builds an evidence-backed record of what a course actually develops in students. You check the course materials, an AI interviewer asks you about the course, and the tool drafts a Course Outcome Profile: the course's competencies, each scored for Knowing, Reasoning and Doing at a depth backed by student evidence, plus the six foundational habits (Agency, Attention to Detail, Resilience, Curiosity, Written Communication, Spoken Communication), scored for Doing only. You review the draft, adjust what is wrong, and approve it. Approval records a permanent, dated snapshot.

What-ifs are for trying out a change to a course once it has an approved version, without changing the course. See §9.

Just want the steps?

The step-by-step how-to walks through a capture screen by screen, with screenshots. This guide explains what each step does and why.

02

How you reach the tool

The tool runs on the Clemson network. There is no off-campus access; use the campus VPN when you are away.

  • Home page: https://gcworkflow.clemson.edu:8443/ lists every course with its capture status. Anyone on the network can browse it and open a course's read-only public profile.
  • Faculty pages (CourseCapture, what-ifs, the course list, the program matrix) need a login. GC faculty use the shared faculty username and password, asked once per browser. Faculty who edit only their own course get a personal link from the administrator: clicking it signs them in on that browser for 30 days at a time, and they can change only the courses it lists. Don't share a personal link.
  • Voice input works on the https://…:8443 address. Browsers block the microphone on plain http:// pages, so if the Voice button is refused, check that the address starts with https.
03

Before you start

  • The course must be on the course list. If it is missing, use + Add a course on the course list, or ask the administrator. A lecture/lab pair (e.g. GC 3460 + GC 3461) is captured as one bundled course.
  • Have the syllabus ready. A syllabus is required: it is the source of the course's stated objectives. Canvas's syllabus page counts, or upload a PDF or Word file.
  • Gather what students actually do: assignment sheets, rubrics, project briefs, quizzes, lecture slides. The profile can only score what it can see evidence for, so thin materials make a thin record.
  • Allow 20–45 minutes for a first capture. You can stop at any point; the interview is saved and picks up where you left off.
04

Step 1 · Check your materials

The first screen shows everything the interviewer will read, in three boxes. Open each one to see what is inside and add what is missing.

  • Canvas — assignments, quizzes, pages, modules, the Canvas syllabus and Canvas files. Import from Canvas / Reimport needs a Canvas API token. Scan linked docs follows Google Docs, Drive PDFs and YouTube links inside your Canvas content and pulls them in.
  • Syllabus & course info — the syllabus (required) and, for courses that have one, the course's row on the GC course sheet. Upload a syllabus here if Canvas doesn't have one.
  • Other materials — anything else: slides, rubrics, handouts, exemplars. PDF, Word, PowerPoint, Excel, CSV (a Canvas rubric export, for example), web pages and images are read; scanned PDFs are read with OCR.

Pick your name under I'm the instructor so the capture is attributed to you, then click Continue →. The step won't continue without a syllabus.

If the course has almost nothing to work from (a syllabus alone, or files that were never read), the interview opens with a warning: This capture has very little to work from. You can add materials first or click Continue anyway; the profile will be thin, and approving it later asks you to confirm that.

Privacy

Before anything is stored, the tool removes email addresses, Social Security numbers and CU ID numbers from the text it reads (instructor contact details in a syllabus are kept). The original files are not changed. The AI service is covered by Clemson's education contract.

05

Step 2 · Choose how closely to read each file

Reading every file in full is slow and not always useful, so each file gets a level. The tool makes a first guess; your job is to check it.

LevelWhat the tool doesUse it for
High: read in fullEvery passage is stored and can be quoted as evidence; pictures are described.The syllabus and anything graded: assignments, rubrics, quizzes, exams.
Middle: summarized slide by slideEach slide or section becomes a short note of what it teaches; title-only and image-only slides are dropped.Lecture slides, class pages.
Background: one summaryThe whole file becomes one paragraph. The tool knows what it covers but can't quote it.Readings, references.

Why it matters: a score above the basics needs evidence that students actually did the work, so anything graded must be High or it can't count as evidence. Use ▲ ▼ to move a file, ignore to leave it out, delete to remove it. Moving a file that was already read re-reads it at the new level.

A file you leave out (it shows as set aside) or retire is never shown to the AI: not to the interviewer, its search, or the scoring. It stays on the list so you can bring it back.

Click Read files & continue. The estimate beside the button counts only files not yet read. When reading finishes you go on to the interview automatically; the step stops only if a file couldn't be read, so you can go back and replace it or continue without it.

06

Step 3 · The interview

For a first capture, pick your name and click Start the interview. If the course already has an approved version, you are first asked What's changed in this course since it was approved? See §8 for the three answers.

What the interviewer is doing

It has read your materials and can search them during the conversation. It also knows the profiles of the courses that feed into yours and the courses that build on it, from the Clemson catalog's prerequisites, so it can ask about hand-offs ("GC 4060 expects students to arrive able to … — does your course prepare them for that?"). Those neighboring courses are context for its questions, never evidence for your scores. It checks:

  • what students actually produce and how it is graded, as opposed to what the syllabus aspires to;
  • how deeply students know, reason about and do each thing;
  • whether the stated objectives match the evidence;
  • where students struggle, fail and revise.

Answering

Each turn ends with a highlighted Question for you. Type a reply (Enter sends, Shift+Enter adds a line) or click Voice to speak it; the first recording can take a few seconds to start. Specific answers ("students submit a press-ready PDF and I grade it against this preflight checklist") produce a much stronger profile than general ones. The reply box takes text only: to share a document mid-interview, paste its text into the reply, or add the file under Materials. If a document the interviewer can't open (a video, an external tool) matters, describe what is in it.

The interview checklist

Beside the chat, the Interview checklist shows what the interviewer still wants to cover (Still to cover) and what it has checked off so far (Covered, newest first, with the latest items highlighted). It updates after each turn and is kept when you come back. It is a guide, not a gate.

Stopping and resuming

Your answers are saved after each turn. Open the course again and you return to the conversation. Where we left off summarizes earlier sessions.

Finishing

Click I'm done — give me one last question. The interviewer looks back over the conversation and asks the single most important question still missing. Answer it, then click Generate Profile.

07

Step 4 · Generate, check outcomes, review and approve

Generating

Generating takes about two minutes. One pass reads the whole interview and your materials, identifies the course's competencies (typically 5–15) and scores each one. Any score above the basics must carry an evidence excerpt that traces back to a real passage in your materials or a turn in the interview; results that don't check out are rejected and redone. The result is a draft. Nothing is recorded yet.

Checking the outcomes

Two short screens come first: Apparent outcomes (what students can do by the end, as the interview read it) and Incoming skills (what the course assumes students arrive with). Each has three choices:

  • ✓ Looks good — proceed;
  • Add or change something — describe the change and the tool suggests the edit for you to accept or discard;
  • ← Back to the interview — if it missed something important.

Reviewing the profile

The review page starts with Does this capture your course?, an overview of what the interview found. Below it, the competencies are listed in course order. A second AI review runs automatically after generating and checks each score against the evidence; the cards it, or the interviewer, was least sure about are highlighted as worth a look, each with the reason.

Each highlighted card needs a decision:

  • ✓ Looks right if it is correct;
  • Needs adjusting to change a score: click Change beside Knowing, Reasoning or Doing, pick the description that fits, and Save changes. Raising a score asks you for the evidence, which is stored as the reason.

Tags on each card say where a reading came from: From your interview, From course materials, From your interview and course materials (you said it and a course document backs it), or AI's inference. Click a citation to see the passage. Flag this reading records a disagreement that stays visible until someone resolves it. Save draft keeps your changes without approving.

If the overview gets the course badly wrong (not just a score or two), use ← Back to the interview, tell the interviewer what it missed, and generate again.

When you are revising a course that already has an approved version, the review page also lists what moved since that version (see §8).

Approving

When every highlighted card is done, Approve the profile unlocks at the bottom of the page (it reads Approve update for a course that already has a snapshot). Add an optional caption and note. If the capture had very little to work from, you also tick Approve anyway to confirm the profile rests on thin evidence. Approval records a permanent, dated snapshot; the green Captured card confirms it. The course's public profile, the program coverage matrix and the curriculum wiki update from it automatically.

08

Snapshots and re-capturing

Every approval adds a dated snapshot; nothing is overwritten. The working draft stays editable after approval, and later changes are recorded with Approve update as a new snapshot.

The Snapshots panel (under Setup & history on the interview step, or the N versions link on the course list) lists them. For each one:

  • view opens a read-only summary;
  • use as draft replaces the current working draft with that snapshot's profile (the snapshots themselves are untouched);
  • retire hides a snapshot that no longer describes the course; restore brings it back.

When to re-capture

Re-capture after a substantive change: new or redesigned assignments, a change of instructor, a shift in what the course emphasizes. Open the course and answer What's changed in this course since it was approved?

  • A few specific things changed: tell the interviewer what changed. Every rating is checked again, but a rating that moves without new evidence is set back to the approved version for you.
  • Re-check the whole course: the approved version is the starting point, and every rating is checked again against your current materials and the conversation.
  • Start over: a new profile from your current materials and the catalog, as if for the first time.

In every case the approved version stays in place until you approve the new one. For the first two, the review page shows what changed, split into changes with new evidence and changes without it (likely AI variation, which you can undo or keep). Decide on each before approving. Ratings that cite a file since retired or set aside are listed under Evidence no longer in use so you can check them.

09

What-ifs · trying out a change

A what-if lets you sketch a change to a course and see what it would mean before anyone commits to it: "what if GC 3400 added a packaging project and dropped the second poster?" You describe the change in a conversation, and the tool writes a page that reads like the course's wiki page, with the change in place and its likely effect on neighboring courses and career targets. It is meant as a starting point for a conversation with the people who teach the courses before and after.

Nothing in the course changes

A what-if is kept apart from the real course. Its conversation, files and page are stored on their own and never reach the course's draft, its approved versions, its materials, the program views or the public wiki. Someone revising the course for real at the same time sees no difference.

Starting one

A what-if starts from the course's current approved version, so the course needs one. There are two ways in:

  • on the course's interview page, Try a what-if instead, set apart from the three re-capture choices;
  • on the course's what-if list (What-ifs on the course list, or the faculty view of the course's wiki page), the same control.

Under the shared department login you pick your name first, so the page can say who wrote it. You can start a what-if on any course, not only your own: the instructor of the next course is often the one asking "what if the course before mine added this?"

The conversation

The assistant asks what you want to change, or what result you are after. If you know the result but not the change ("students should arrive in my course able to soft-proof"), it suggests a few possible changes, says what each would push out, and can give a quick predicted effect for one you want to weigh. It does not pick for you. Once there is a direction, it asks one question at a time until it knows what is added, what comes out to make room, what students would need walking in, and what they would leave with. Its statements about other courses come from the curriculum record, not from general knowledge.

Type or use Voice. Attach files to add a draft assignment, a rubric or a screenshot: pick files, drop them in, or paste an image. Attachments are read the same way as course materials, including the screening for student information, and are used only by this what-if. A file that cannot be read is marked in the conversation.

The page

When you are ready, Create the what-if page. This takes a minute or two. The page has a banner saying it is a what-if, then:

  • What changes: what is added and removed, what students would newly need walking in, and the ratings that would move, before and after, each with a confidence and a reason. If removals never came up, it says "Removed: not discussed" rather than implying nothing comes out.
  • The course as it would be: the course description rewritten with the change, and the full table of ratings.
  • For neighboring courses: whether earlier courses deliver what this would newly ask of them, prerequisite gaps that later courses would gain or lose, and career targets that would move. Only confirmed prerequisite links are checked. Where an effect could not be worked out, the page says so instead of reporting no effect.
  • Questions for discussion and what it is based on (the attached files).

You can go back to the conversation, say more or attach more, and Update the page. Updating replaces the page. You can also rename or delete the what-if; deleting removes the page, the conversation and the files, and cannot be undone.

What "predicted" means

Ratings the change does not touch keep their approved values exactly. Ratings it would move, and any new ones, are marked predicted: they are estimates of what the course would develop once the change is taught, not measurements. The evidence rule for approved ratings does not apply to them, because nothing has been taught yet. A full capture after the change is taught is what records it for real. The AI writes the page's wording only; every rating and effect on the page comes from the stored estimate.

Who can see and change it

  • Once it has a page, a what-if is listed for the course and anyone signed in can read it. Share it by passing on its link.
  • Until then, and for its conversation, only the person who started it (and an administrator) can see it.
  • Only the person who started it, or an administrator, can continue, update, rename or delete it. Under the shared department login, the login is the owner, so anyone using that login can do these things.

If a newer version of the course is approved later, the page says so and can still be updated against the version it started from. If that version is withdrawn, the page stays readable but can no longer be updated.

Each what-if calls the AI and counts toward the department's daily AI spending limit, like the interview.

10

The course list and prerequisites

The course list (/courses)

Courses are grouped by level, with counts by status at the top. Each row shows:

  • a data badge: Measured (captured from evidence), Syllabus or No data;
  • a status: Captured, Reviewed, AI drafted, In audit or Not started, and the last capture date;
  • the main action: Capture Course if not started, Edit Course otherwise;
  • View Course (the public profile), What-ifs (with a count when there are any), N versions (the Snapshots panel) and Prereqs.

+ Add a course adds one course (code, title, level, track, catalog URL). Preload courses adds many at once, one per line.

Prerequisites

The tool takes prerequisites from the Clemson catalog, falling back to the GC course sheet only for a course the catalog doesn't list. The interviewer, the profile and the wiki all use this.

The Prereqs page for a course (/courses/<code>) lets you record skill-level prerequisite links: which competency, at what Knowing / Reasoning / Doing depth, a course needs from each prerequisite. Seed from syllabus prerequisites drafts them with AI; you confirm, edit or delete each one. The gap view below compares what each prerequisite delivers (from its captured profile) with what this course needs, using confirmed links only: Met, Gap or No data.

Note

The text headed "Catalog prerequisites" on that page is still the GC course sheet's wording, not the Clemson catalog list used everywhere else.

11

The public profile

Every captured course has a public page at /view/<course-code> (View Course on the course list). Anyone on the Clemson network can open it without logging in, which makes it the link to share with a chair, a colleague or an accreditation reviewer. It shows the latest snapshot's outcomes and what the course develops, with a Markdown download and a print button. Courses not yet captured show their catalog description instead.

It does not show the interview transcript, the review notes or individual scoring evidence. Those stay on the faculty pages. Student emails and ID numbers never appear: they are removed before anything is stored.

The curriculum wiki (/wiki) is also public and is rebuilt from each new snapshot.

12

Tips

  • Put graded work in High. It is the evidence the scores rest on.
  • Be concrete. "Students preflight their own files against a checklist and fix every error before submission" beats "students learn preflight."
  • Don't pad the habits. A foundational habit (Agency, Attention to Detail, Resilience, Curiosity, Written or Spoken Communication) at Doing "not yet" is a real finding: it shows where in the program the habit is and isn't developed.
  • Describe what the tool can't open. Videos on Vimeo, Panopto, Kaltura or Canvas Studio, and external tools, are noted but not read. Tell the interviewer what is in them.
  • Use Voice for long explanations and typing for short corrections.
  • If a page acts strangely right after the tool was updated, reload it (Shift-Reload).
  • If a notice says the AI is paused, Clemson's shared AI credits have run out. Your saved work is safe and the administrator has been told; try again later.
13

What these tools don't do

  • Not an evaluation of any instructor or student. Scores describe what the course's work requires and evidences.
  • Not automatic redesign. A what-if predicts and suggests; faculty decide, and a re-capture records the change once it is taught.
  • Not a replacement for your judgment. The AI drafts; you confirm. Every score is editable.
  • No snapshot comparison yet. You can read snapshots one at a time, but there is no side-by-side view of what changed.

For what Knowing, Reasoning and Doing depth mean and what counts as evidence, see the KUD+ Background document. For where the program is heading, see the Vision document.
