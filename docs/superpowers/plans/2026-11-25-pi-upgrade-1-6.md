# Pi 1.4 → 1.6.1 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the interviewer's Pi packages from 1.4.0 to 1.6.1 with no change in interview behavior, verified before the staged-interview rebuild starts.

**Architecture:** Only `@earendil-works/pi-agent-core` and `@earendil-works/pi-ai` are used, and only in `lib/ai/agent/pi/turn.ts`, `lib/ai/agent/pi/task.ts` and their tests. Bump both, fix what the type-checker and tests report, then compare the 29-case interview benchmark before and after on campus models.

**Tech Stack:** TypeScript, pnpm, Vitest, Pi (`@earendil-works/*`).

**Spec:** `docs/superpowers/specs/2026-11-25-interview-stages-design.md` (section "Step 1: Pi upgrade").

## Global Constraints

- Versions: `@earendil-works/pi-agent-core` and `@earendil-works/pi-ai` both exactly `1.6.1` (no caret).
- No interview behavior change. Prompts, tools, temperature (0.2) and the token cap (16000) all stay the same.
- Benchmark runs use campus models only (free); `AI_PROVIDER=campus`, the scratch DB `gc_curriculum_p2_scratch` with `--expect-db`.
- The one Terra probe costs a few cents. It needs a hard cap in code (`--max-usd 0.10`), and the owner already approved "upgrade first" (2026-11-25).
- If any check fails and can't be fixed within this plan, stop: add a STATE.md Deferred/debt line ("Pi upgrade held: <reason>") and do not merge. The rebuild proceeds on 1.4.0 (spec ruling 6).
- Work in a git worktree off `dev`, never the main checkout; stage by path.

## Review Focus

1. `submit_turn` arguments rejected by the new `pi-schema` validator: nullable unions (`['string','null']`) and long excerpts. Expect the same acceptance as 1.4.
2. Forcing a specific tool on a request (`tool_choice` for `search_materials` / `submit_turn`) still works in `pi-agent-core` 1.6.1.
3. Reasoning effort is still sent for `gpt-6.1-terra: medium` (`DEFAULT_REASONING_EFFORT`).
4. Pi's ESM-only dynamic `import()` paths still resolve under Next's server build. These are `@earendil-works/pi-ai/api/openai-completions.lazy` and `openai-responses.lazy`.
5. Token and cost telemetry fields still read correctly after the 1.5.0 `Usage.cost` changes.
